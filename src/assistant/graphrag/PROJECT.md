# Готовое решение: ассистент сервисной службы

Индивидуальный проект: Велимир Миронов, GitHub **PohjoinenJohtaja**.
Репозиторий: https://github.com/PohjoinenJohtaja/llm-project

Ассистент связывает модель оборудования, ошибку, узел, деталь и её замену,
получает цену и остаток из ERP и передаёт создание заказа на подтверждение человеку.
Реализованы все шесть модулей задания. Исходный README сохранён как текст задания.

## Архитектура и принятые решения

1. extraction.py: структурированный ответ LLM, канонизация и проверка фактов по чанку.
   Длинные списки состава оборудования разбиваются на группы по три строки;
   сохраняется исходный ID чанка, поэтому повторения не увеличивают вес связи.
2. graph_builder.py: объединение сущностей в DiGraph, источники, веса по уникальным
   чанкам и разрешение конфликтов направлений замены.
3. communities.py: Louvain с seed=42; числа считает код, LLM пишет сводки до 150 слов.
4. search.py: local выбирает ограниченные пути и цепочки замен; global использует
   map/reduce по сводкам. Это разные режимы с разными ограничениями.
5. ../agent/tools.py: пять инструментов поиска и ERP, проверка аргументов.
6. ../agent/agent.py: ограниченный цикл, проверка кодов и количества, повторы ERP,
   защита от необоснованных ответов и обязательное подтверждение заказа.

При confirm=False возвращаются needs_confirmation и pending_action; заказ
не создаётся. При confirm=True номер должен быть получен от успешного инструмента.
Запрос количества уточняется, если пользователь его не назвал.

| agent | 70,8% | 0,875 | 0% | 5,125 | 3737,000 |

Модель: Qwen3 4B Instruct 2507 Q4_K_M через Ollama 0.15.4; эмбеддинги bge-m3-cpu.
Граф: 92 чанка полного корпуса, 118 узлов, 269 рёбер, 8 сообществ, 0 конфликтов.
Извлечение связей на эталоне: Precision 0,975, Recall 0,963.
Индексация: 138 вызовов, 172764 входных и 48278 выходных токенов.
Кешированные вызовы тоже учитываются в стоимости штатного оценщика.

В сохранённых проверках прошли 164 теста и lint; Docker, HTTP API и реальное
создание учебного ERP-заказа проверены. Полные оценки воспроизводятся с кешем;
отдельная проверка свежего ответа и эмбеддинга не является свежим полным benchmark.
Скрытые вопросы не доступны и не проверены. Ноль в fabricated_rate не гарантирует
семантическую правильность: см. анализ ограничений метрики.

## Авторство и готовность к сдаче

Проект выполняется одним участником. Использовались ChatGPT/Codex для реализации,
диагностики, тестирования и оформления; Codespaces и Colab — для вычислений.
Подробное описание вклада и использования ИИ войдёт в REPORT.pdf.
PDF пока не создан. Метка v1.0 ставится только на окончательный коммит с PDF.
Оценки получены на разработческом наборе; изменения подбирались с учётом его ошибок.
Это не независимая оценка обобщения на новых вопросах.
